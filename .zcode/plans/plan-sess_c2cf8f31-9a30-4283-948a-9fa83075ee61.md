# Gentry 全规则化改造 + 移除价格监控 + 架构简化方案

## 总体思路

改造后系统只保留一条主线：**已保存规则（数据库模板 + 外部规则文件 + JSON API 规则）→ CSS 选择器/JSON path 提取 → 与 UpdateRecord 历史比对 → 新增条目同步推送**。

三项核心工作：
1. **移除价格监控**：field_transition 策略、money 解析、价格快照/事件/异步投递队列全链路删除。
2. **扫描全规则化**：删除启发式引擎（keyword_ancestor / repeated_list / link_cluster / table_rows 四策略及全部评分合并机制，约 800 行）。监控识别和高级规则页都只按规则命中；规则改为手动填写 + 实时测试 + JSON 导入。
3. **架构简化**：删除只服务于价格监控的 Engine 持久化子系统（MonitorSnapshot / MonitorEvent / NotificationDelivery / 投递 worker），presence 保留现有 UpdateRecord + 同步通知路径（功能不变）。

关键事实（已核实）：生产代码中 Engine.CheckOnce 只被 field_transition 分支调用；启发式策略只在高级规则页的"发现模式"（strategy_type 为空）运行；`/monitors/smart-create` 前端已不调用，属遗留端点。

## 风险与说明

- 旧数据库不做表结构 DROP（只删 field_transition 数据行），删除的列留在库里不被读写，保证可回滚。
- presence 的通知仍是同步发送（现状即如此），异步投递队列只服务过价格事件，随之删除。
- Extractor 中两个"旧配置修复"启发式（recoverLegacyMetadataItemSelector / narrowLegacyBroadContainers）服务于已保存配置的提取鲁棒性，保留（功能不变优先）。
