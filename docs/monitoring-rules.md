# 监控规则说明

Gentry 将网页抓取结果转换为带稳定身份的观测记录，再与上一次快照比较。不同监控类型共用抓取、提取、规范化、事件持久化和通知投递链路。

## 网页新增监控

网页新增监控使用 `presence` 策略，适合公告、新闻、更新日志和商品上新列表。

- 首次成功检查建立基线，不推送页面中已有条目。
- 后续出现新的 `item_key` 时产生新增事件。
- 列表内容必须具有稳定身份，不能依赖随排序变化的位置索引。

常见身份字段包括文章 URL、公告编号和商品 SKU。

## 价格下降监控

价格监控使用 `field_transition` 策略，当前支持金额字段。

“价格发生下降”会在当前有效价格低于上一次有效价格时触发。可以配置：

- 任意降价即通知；
- 最低降价金额；
- 最低降价百分比；
- 同时满足最低金额和最低百分比。

价格短暂解析失败时，不会用无效值覆盖最后一次有效基线。币种发生变化时也不会直接跨币种比较。

## 到价提醒

“降到目标价及以下”采用跨边界语义。目标价格为 `X` 时：

- `100 → X`：通知；
- `100 → 小于 X`：通知；
- `X → 更低价格`：不重复通知；
- `低于 X → 高于 X`：不通知，但重新进入等待状态；
- 再次从高于 X 降到 X 或以下：再次通知；
- 首次基线已经低于 X：不通知。

这种语义可以避免监控周期内持续低价造成重复推送。

## 商品身份

系统必须能够在两次检查中识别同一个商品：

- 单商品详情页可以使用网页 URL 作为身份。
- 商品列表页必须使用稳定且唯一的字段，例如 SKU、商品详情链接或商品 ID。
- 价格字段不能作为身份，因为价格本身会发生变化。
- 不允许使用 `item_0` 一类列表位置作为身份。

## 基线

新建监控、手动重置基线，或者修改 URL、选择器、字段、商品身份、价格字段和价格规则后，需要重新建立基线。

名称、检查间隔和通知账户等不影响检测语义的修改，不应触发基线重建。

## 推送过滤

检测规则决定是否产生变化事件，推送过滤决定事件是否发送到通知账户：

- `all`：所有符合检测规则的变化都推送。
- `keyword`：仅当变化内容命中配置的关键词时推送。

即使没有配置推送账户，变化事件和更新记录仍会保存在数据库中。

## 扫描规则与监控规则

“扫描规则”是预扫描阶段复用的提取模板，不是变化检测条件。HTML 规则保存容器、列表项和 CSS 字段选择器；JSON API 规则保存接口、数组路径、过滤条件和字段路径。两种监控类型共用同一套规则，并通过以下范围控制参与哪些 URL 的候选生成：

- `exact`：当前页面，匹配主机、路径和查询参数。
- `route`：当前路由，按路径段前缀匹配；查询路由继续保留查询参数约束。
- `section`：同站目录，匹配同一主机、同一父目录下的页面，例如 `/products/adguard` 与 `/products/reqable`。
- `global`：通用结构，在所有网站上尝试结构选择器。

适用范围由用户在保存规则时选择，系统默认使用最严格的 `exact`。价格预扫描优先返回已命中的规则候选。扫描规则只帮助生成候选；监控运行时仍使用监控自身保存的提取配置。因此，删除或导入扫描规则不会追溯修改已有监控。

站点提取规则不会在程序中逐个内置。首次接入网站时，在监控的高级数据源中配置 HTML/CSS 或公开 JSON API，验证后另存为规则模板；后续网页与价格预扫描都按规则适用范围命中。规则中的接口 URL、过滤条件、受控请求头和字段路径都会随规则一起导入、导出。

同一商城的不同商品若共用接口结构，可以在 API URL 和受控请求头中使用 `{{参数名}}`。参数通过 CSS 选择器从当前商品页读取；例如 `#goods_id` 的 `value` 可以替换 `goods_id={{goods_id}}`。内置变量 `{{page_url}}` 表示当前监控的商品页 URL，适合用于 `Referer`。变量不能替换 API URL 的协议或主机。

扫描规则页面可以直接切换“网页规则”和“价格 API 规则”。价格规则支持在保存前测试接口提取，并配置页面范围、页面动态参数、JSON 列表与过滤路径、SKU/价格字段映射以及受控请求头。价格规则默认使用“同站目录”范围。

可选导入示例见 [`lizhi-adguard-scan-rule.example.json`](lizhi-adguard-scan-rule.example.json)。示例文件不会被程序自动加载。

旧版 `URLContains` 模板仍然兼容，但新规则不再使用容易跨路由误匹配的 URL 子串作为默认范围。

## 页面限制

默认抓取器适合服务端直接返回完整 HTML 的页面，也支持无需登录的公开 JSON API。对于多规格商品，应优先使用接口中的稳定 SKU 和价格字段。若页面只能在浏览器执行 JavaScript 后取价且没有公开接口，或者依赖登录、验证码和复杂风控，普通 HTTP 抓取仍无法获取有效数据。
