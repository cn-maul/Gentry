# 监控规则说明

Gentry 是一个规则驱动的网页新内容监控系统：按已保存的扫描规则识别页面内容结构，提取条目后与历史记录比对，发现新条目时推送通知。

## 网页新增监控

所有监控都使用 `presence`（新增检测）语义，适合公告、新闻、更新日志和上新列表。

- 首次成功检查建立基线，不推送页面中已有条目。
- 后续出现新的条目（按标题 + 链接 去重）时生成更新记录并推送。
- 修改 URL、容器、条目或字段等影响提取语义的配置后，需要重新建立基线。

名称、检查间隔和通知账户等不影响检测语义的修改，不会触发基线重建。

## 扫描规则（唯一的内容识别来源）

监控创建页的“自动识别”与高级规则页完全依赖扫描规则，没有内置的启发式猜测。规则分为两类：

- HTML 规则：保存容器选择器、条目选择器和 CSS 字段选择器。
- JSON API 规则：保存接口 URL、数组路径、过滤条件、动态参数、受控请求头和字段路径。

规则通过适用范围控制参与哪些 URL 的识别：

- `exact`：当前页面，匹配主机、路径和查询参数。
- `route`：当前路由，按路径段前缀匹配；查询路由继续保留查询参数约束。
- `section`：同站目录，匹配同一主机、同一父目录下的页面，例如 `/products/adguard` 与 `/products/reqable`。
- `global`：通用结构，在所有网站上尝试结构选择器。

适用范围由用户在保存规则时选择，系统默认使用最严格的 `exact`。多条规则同时命中时按优先级从高到低返回候选。

扫描规则只帮助生成监控配置；监控运行时使用自身保存的提取配置副本。因此，删除或导入扫描规则不会追溯修改已有监控。

## 创建规则

规则在「高级规则」页手动创建，支持网页 HTML 和公开 JSON API 两种数据源：

1. 填写规则名称和页面 URL。
2. 选择数据源并填写选择器（或 JSON 路径）与提取字段（必须包含 `title` 字段）。
3. 使用「测试提取」对页面实际运行一次提取，确认样本正确。
4. 选择适用范围并保存。

也可以从「新增监控」页把已验证的提取配置「另存为扫描规则」，或通过导入功能批量添加规则库。

同一站点不同页面若共用接口结构，可以在 API URL 和受控请求头中使用 `{{参数名}}`。参数通过 CSS 选择器从当前页面读取；例如 `#goods_id` 的 `value` 可以替换 `goods_id={{goods_id}}`。内置变量 `{{page_url}}` 表示当前监控的页面 URL，适合用于 `Referer`。变量不能替换 API URL 的协议或主机。

可选导入示例见 [`lizhi-adguard-scan-rule.example.json`](lizhi-adguard-scan-rule.example.json)。示例文件不会被程序自动加载。

旧版 `URLContains` 模板仍然兼容，但新规则不再使用容易跨路由误匹配的 URL 子串作为默认范围。

## 推送过滤

- `all`：所有新内容都推送。
- `keyword`：仅当变化内容命中配置的关键词时推送。

即使没有配置推送账户，更新记录仍会保存在数据库中。

## 页面限制

默认抓取器适合服务端直接返回完整 HTML 的页面，也支持无需登录的公开 JSON API。若页面只能在浏览器执行 JavaScript 后才能获取数据，或者依赖登录、验证码和复杂风控，普通 HTTP 抓取无法获取有效数据。
