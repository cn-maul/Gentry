# 快速开始

## Docker Compose

项目根目录已经提供 `docker-compose.yml`：

```bash
docker compose up -d --build
docker compose logs -f
```

启动后访问 [http://localhost:8080](http://localhost:8080)（单服务：界面与 API 同端口，前端已嵌入二进制）。停止服务使用：

```bash
docker compose down
```

普通停止不会删除数据库。只有执行 `docker compose down -v` 才会同时删除 `gentry-data` 数据卷。

## 本地运行

环境要求：

- Go 1.27
- Node.js 22 或兼容版本
- npm（前端依赖与构建统一使用 npm）

在 `backend/` 目录下构建前端并编译后端：

```bash
cd backend
make build
make run
```

Windows 也可以运行项目根目录的 `build.bat` 或 `build.ps1`（自动构建前端、拷贝产物并编译嵌入二进制）。

默认地址为 [http://localhost:8080](http://localhost:8080)。可通过 `PORT` 环境变量修改端口。

## 开发模式

后端：

```bash
make dev
```

另一个终端启动前端（开发模式下 Vite 会把 `/api` 代理到本地 8080）：

```bash
cd frontend
npm install
npm run dev
```

开发界面默认运行在 [http://localhost:5173](http://localhost:5173)。

## 创建扫描规则

内容识别完全依赖已保存的扫描规则。第一次监控某类页面时，先创建规则：

1. 打开「高级规则」页。
2. 填写页面 URL（规则名称可在确认配置后再填）。
3. 填写容器/条目选择器和提取字段（必须包含 `title` 字段），点击「测试提取」确认样本正确；也可以填写关键词后点击「AI 提取」，让 AI 自动识别并回填选择器（需先在「设置」页配置 AI 模型）。
4. 选择「当前页面」「当前路由」「同站目录」或「通用结构」后保存。

默认选择“当前页面”。只有同一路由的子页面确实使用相同结构时才选择“当前路由”；只有多个网站使用同一套结构时才选择“通用结构”。

规则页面支持导出和导入 JSON。导入时同名规则会跳过，不会覆盖现有规则。

## 创建网页监控

1. 打开「新增监控」。
2. 填写名称、网页 URL、分组和检查间隔。
3. 点击「按规则识别内容」；系统按已保存规则返回候选，确认样本正确的候选区域。未命中规则时，先到「高级规则」页创建规则，或展开"高级设置"手动配置选择器。
4. 选择推送全部新内容或仅推送命中关键词的内容，并选择通知账户。
5. 执行配置验证，确认能够稳定提取条目后保存。

首次检查只记录当前条目，之后出现新条目（按「标题 + 链接」去重）时才产生通知。也可以把已验证的提取配置「另存为扫描规则」，供以后配置相同结构的页面。

## 配置通知

1. 打开“推送管理”并启用全局通知。
2. 新建 PushPlus、Webhook、Server酱或 Bark 账户。
3. 在新增监控或监控详情中勾选需要使用的账户。

没有选择推送账户时，系统仍会保存更新记录，但不会发送通知。

## 日常操作

仪表盘可以启动、暂停、编辑或删除监控器。进入监控详情后，可以立即检查、调整推送账户，并查看更新历史。
