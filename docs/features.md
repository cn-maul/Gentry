# 功能总览

本文描述当前代码中已经实现的功能。`design/` 下的文件用于记录历史设计和审查过程，不作为当前功能清单。

## 管理界面

Gentry 提供响应式 Web 管理界面，包含以下页面：

- 仪表盘：查看监控器运行状态、URL、上次检查时间、更新数量和最近错误；可直接启动、暂停、编辑或删除监控器。
- 新增/编辑监控：配置基本信息、内容提取和通知账户，并在保存前验证配置。
- 监控详情：查看运行状态、检查耗时、下次检查时间和基线状态；支持立即检查、调整通知账户和查看更新记录。
- 推送管理：管理全局通知开关和多个推送账户。
- 高级规则：手动创建、AI 辅助识别和维护可复用的扫描规则，并导入或导出规则库。

界面支持亮色和暗色模式，并针对桌面和窄屏设备调整布局。

## 监控类型

### 网页新增监控

所有监控都使用 `presence`（新增检测）语义，适用于公告、新闻、更新日志和上新列表。

- 首次成功检查只建立基线，不把页面已有内容当作新内容推送。
- 后续出现新的条目（按标题 + 链接去重）时生成更新记录。
- 标题、链接、摘要、日期等字段可以通过 CSS 选择器提取。
- 更新历史按较新内容在前的顺序展示。

## 内容提取与识别

每个监控保存一份独立的提取配置：

- `container`：页面中的内容区域。
- `item`：区域中的重复条目。
- `fields`：从每个条目中提取的文本或属性字段。
- `transform`：字段清理和转换配置。
- `fetch_config`：可选的数据源模式；`api_json` 使用公开接口 URL、数组路径、过滤条件和受控请求头。

新增或编辑监控时执行“按规则识别内容”。扫描器遍历所有命中该 URL 的已保存规则，按规则优先级返回候选并显示样本内容；未命中规则时提示先到「高级规则」页创建。用户确认候选后，生成的选择器会应用到监控表单；容器选择器、列表项和字段等手动配置折叠在"高级设置"中，可按需展开调整。

识别只是配置辅助工具，不会自动创建监控或修改已有监控。保存监控后，运行时使用的是该监控自身保存的选择器副本。

## 扫描规则库

扫描规则是内容识别的唯一来源（没有内置启发式猜测）。规则在「高级规则」页创建，支持手动与 AI 两种方式：

**手动创建：**

1. 填写规则名称和页面 URL，选择网页 HTML 或公开 JSON API 数据源。
2. 填写选择器（或 JSON 路径）与提取字段，必须包含 `title` 字段。
3. 使用「测试提取」对页面实际运行一次提取，确认样本正确。
4. 选择适用范围并保存。

**智能捕获（AI 提取）：**

1. 在「设置」页配置 OpenAI 兼容的 AI 模型（接入地址、API Key、模型名称，支持 DeepSeek、通义千问、Moonshot、OpenAI、Ollama 等），可一键测试连通。
2. 在「高级规则」页填写页面 URL 和关键词（正确条目应包含的文字，用于辅助 AI 定位内容区域）。
3. 点击「智能捕获」：统一捕获管线抓取页面、按关键词定位相关片段后交给 AI 分析，生成选择器草稿并在本地实际验证——选择器可编译、能提取条目、条目命中关键词；验证失败会携带错误反馈自动重试一次，鉴权等配置类错误会立即返回明确原因。
4. 通过验证的配置自动回填表单并展示样本与诊断信息；未命中关键词时同样回填，但会提示用户对照样本确认区域是否正确。用户核对后仍可「测试提取」（不落库的草稿直测）再保存。

捕获只产出草稿，系统不会自动创建或修改规则；确认保存走「快速保存」。

也可以从「新增监控」页把已验证的提取配置「另存为扫描规则」。HTML/CSS 与 JSON API 共用同一套规则库；删除规则不会删除监控，也不会改变已经保存到监控中的提取配置。

### 适用范围

| 范围 | 匹配方式 | 适合场景 |
| --- | --- | --- |
| 当前页面 `exact` | 规范化后主机、路径和查询参数完全一致 | 固定列表页；同域名下系统较多时的默认选择 |
| 当前路由 `route` | 主机相同，按路径段前缀匹配；源 URL 有查询参数时继续要求查询参数一致 | 同一路由及子路由使用相同页面框架 |
| 同站目录 `section` | 主机相同，匹配源页面父目录下的页面 | 同一站点不同详情页共用列表结构 |
| 通用结构 `global` | 不限制 URL；只有页面实际存在规则选择器时才生成候选 | 多个网站使用同一套通用网站框架 |

范围不会由系统自动扩大。规则默认使用“当前页面”，用户可以在保存前调整。根路径且没有查询参数时不能创建路由规则，以免退化为整个域名匹配。

查询参数会按规范顺序保存。例如 `?b=2&a=1` 和 `?a=1&b=2` 视为同一页面，而不同参数值不会互相匹配。

### 导入与导出

- 规则库可以导出为版本化 JSON 文件，包含名称、适用范围、选择器、字段、状态和说明。
- 导入前会校验文件版本、CSS 选择器、标题字段和适用范围。
- 单次导入支持 1 到 500 条规则。
- 同名规则会跳过，不覆盖本地已有规则。
- 导入过程使用数据库事务，写入失败时不会保留不完整规则。

旧版本保存的 `URLContains` 规则继续兼容。它们在界面中标记为“旧版”，仍按原来的 URL 子串方式匹配。

## 监控生命周期与基线

- 监控器可以启动、暂停、编辑和删除。
- 支持从详情页立即执行一次检查。
- 新建监控或修改影响检测语义的配置后，首次检查只建立基线，不发送通知。
- 更新历史按每站点保留最近 500 条，进程重启后可以继续比较。
- 配置版本保存在 SQLite 中，用于判断配置变更。

## 通知

当前支持以下推送服务：

- PushPlus：Token 必填，可配置渠道和模板。
- Webhook：URL 必填，默认使用 `POST`。
- Server酱：SendKey 必填，可配置渠道。
- Bark：设备 Key 必填，可配置服务器、分组、提示音和图标。

通知能力包括：

- 全局通知开关。
- 多推送账户管理，敏感配置在接口响应中脱敏。
- 每个监控可以选择零个或多个推送账户。
- 可推送全部新内容，或仅推送包含指定关键词的变化。

## 数据与兼容性

SQLite 数据库保存：

- 监控定义和字段配置；
- 更新历史记录；
- 通知账户；
- 扫描规则及其字段；
- 系统设置。

数据库由 GORM 在启动时自动迁移。从旧版本升级时，已删除的“价格监控”（field_transition）站点及其快照、事件数据会被一次性清理；普通监控的配置和历史不受影响。生产环境仍应定期备份 `gentry.db` 或 Docker 数据卷。

## 访问限制

默认抓取器支持目标服务器直接返回的 HTML，以及无需登录的公开 JSON API。以下页面仍可能无法正常抓取：

- 必须执行 JavaScript 才能生成主体内容；
- 需要登录态、验证码或浏览器指纹；
- 带有 JavaScript 安全验证、WAF 或严格反爬策略；
- 仅在带有登录 Cookie、临时签名或浏览器指纹的网络请求中返回数据。

公开 JSON API 可以配置 `Accept`、`Accept-Language`、`Referer` 和 `X-Requested-With` 请求头；不接受 Cookie、Authorization 等敏感头。其余网站需要独立的浏览器渲染抓取适配器，当前抓取器不会绕过安全验证。
